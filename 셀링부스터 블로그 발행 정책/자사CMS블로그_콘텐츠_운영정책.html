0. 문서의 범위

본 정책은 sellingbooster.io 커뮤니티 블로그에 발행하는 콘텐츠의 제작·검증·형식 기준을 정한다. 원본은 하이훅(Highook)이 생성한 HTML 초안이며, 이를 '워싱'해 발행본을 만드는 전 과정을 다룬다.

네이버 블로그는 별도 정책(네이버블로그_콘텐츠_운영정책)을 따른다. 두 채널은 에디터 구조가 달라 형식 기준을 공유하지 않는다. 자사 CMS는 인라인 스타일이 보존되고, 네이버는 스마트에디터 컴포넌트로 재조립된다.

1. 발행 체계 9월 개편

9월부터 두 트랙을 병행 운영한다. 트랙별로 목적과 제작 방식이 다르므로 일정과 담당을 분리해 관리한다.

트랙발행 요일성격제작 방식
본편월·수·금셀러 실무 가이드. 검색 유입과 서비스 연결이 목적하이훅 초안 → 워싱 → 셀링부스터 기능·데이터 결합
아이템 딥다이브화·목상세 판매 아이템 분석(생활용품·가전·시즌템). 수요 시점 2~3주 선행자사 트렌드 키워드 데이터 중심, 외부 통계 인용 최소화

주 5회 발행 체계이므로 초안 수급과 검증에 걸리는 시간을 역산해 착수한다. 통계 검증이 필요한 주제는 최소 1일, 셀링부스터 화면 캡처가 필요하면 요청·수령 시간을 추가로 확보한다.

본편은 월=소비자 트렌드 · 수=셀러 지식 · 금=커머스별 노하우 로테이션을 유지한다. 아이템 딥다이브는 외부 통계 인용을 최소화해 주 5회 체제의 검증 부하를 관리하는 축이며, 각 편은 상품성 키워드 링크(/trend/keyword/)로 트렌드 페이지와 연결한다.

네이버 파생은 월·수·금 본편만 대상으로 하며 화·목 아이템 편의 파생 여부는 보류 상태다. 연휴 기간(추석 9/25·9/28 등)은 검색 트래픽이 저조해 발행을 건너뛴다.

시즌 콘텐츠: 해당 시즌·이벤트 2~3주 전 발행을 원칙으로 한다. 검색 수요가 오른 뒤 발행하면 이미 상위 노출을 확보한 문서와 경쟁하게 된다. 네이버 버전은 자사 원본 색인 후 2주 시차가 필요하므로, 시즌 콘텐츠는 자사 발행 시점을 더 앞당겨 역산한다.

2. 콘텐츠 검증 기준 최우선

하이훅 초안은 검증되지 않은 통계와 실존 확인이 불가한 인용을 다량 포함한다. 형식보다 이 검증이 우선이며, 통과하지 못한 요소는 삭제한다.

3-1. 셀링부스터 기능 연결

기능 소개가 목적이 아니라 독자의 문제 해결 흐름에 자연스럽게 놓이는 것이 기준이다. 억지로 끼워 넣으면 광고로 읽혀 이탈한다.

기능경로연결 문맥

기능 언급 시 실측 데이터를 함께 제시하면 설득력이 크게 오른다. 화면 캡처가 필요하면 작업 전 요청하고, 확보되지 않으면 텍스트 서술로 대체하되 없는 수치를 지어내지 않는다.

4. 디자인·형식 규격 다크모드 대응

전제: CMS는 class와 외부 CSS를 제거하고 인라인 스타일만 보존한다. 미디어쿼리를 쓸 수 없으므로 라이트·다크 양쪽에서 성립하는 값을 인라인으로 지정해야 한다.

4-1. 색상 원칙

  • 흰색 등 고정 색상 금지 → 반투명 rgba 사용
  • 텍스트 색은 고정하지 않고 테마 상속. 보라 계열(#6466FA)을 본문 글자색으로 쓰면 다크모드에서 대비가 무너진다
  • 브랜드 컬러는 배경·테두리로 표현. 칩 텍스트만 예외적으로 #7B7DFF(양쪽 모드 대비 확보 가능한 중간값) + !important

4-2. 요소별 규격

요소스타일
상단 인용 박스background: rgba(235,235,235,0.4), padding 18px 22px, radius 12px, border none (좌측 세로선 제거를 위해 border-left: none 병기)
h2 헤드라인24px, border-left: 5px solid #6466FA, padding-left 14px. 크기는 !important + 내부 span 중복 지정(스킨 CSS 오버라이드 회피)
h3 섹션20px, border-left: 5px solid #6466FA, padding-left 14px
h4 소제목17px, border-left: 3px solid #00B1BD, padding-left 11px
표border-collapse: collapse + 모든 th/td에 border: 1px solid rgba(128,128,128,0.3) 균일 적용.
헤더: background-color: #1E2532, 흰 글씨, 중앙 정렬(th와 내부 p 모두), padding 11px 14px, 13.5px
셀: padding 11px 14px, 14px, line-height 1.65, 내부 p margin: 0
colgroup으로 열 비율 지정
이미지border-radius: 30px; max-width: 750px; width: 100%; height: auto; + referrerpolicy="no-referrer" + class="editor-image". 고정 width 속성 미사용
본문 링크color: #00B1BD + target="_blank" rel="noopener noreferrer"
강조(형광펜)background: linear-gradient(transparent 62%, rgba(100,102,250,0.28) 62%). 텍스트 색을 건드리지 않아 다크모드 안전. 한 글 6곳 내외로 절제하며 위치는 재량 판단(핵심 수치·반전 사실·판단 기준)
키워드 배지본문에서 특정 키워드를 지칭할 때: background: rgba(100,102,250,0.12); padding: 1px 7px; border-radius: 5px; font-weight: 700; + 따옴표. 형광펜과 모양이 달라 충돌하지 않음
FAQ 스페이서Q&A 블록 사이 <p><br></p>. 빈 <p></p>는 에디터가 접어버림. 마지막 답변~참고자료 사이는 <p><br><br></p>
하단 키워드 칩박스: background: rgba(128,128,128,0.08), padding 24px 26px, radius 18px
칩 8개: background: rgba(100,102,250,0.1), border: 1px solid rgba(100,102,250,0.38), radius 20px, padding 7px 15px, color: #7B7DFF !important

4-3. 금지 사항

on* 이벤트 속성 절대 삽입 금지. onmouseover·onmouseout을 넣으면 CMS sanitizer가 해당 태그를 정리하면서 style 속성까지 함께 제거해 본문 스타일이 통째로 깨진다. 실측 확인된 사항이다.
항목상태사유
호버 효과보류인라인 이벤트는 위 사유로 사용 불가. 스킨 CSS 속성 선택자 등록이 유일한 방법이며 현재 미적용
표 라디우스보류collapse에서는 브라우저가 무시하고, separate로 바꾸면 셀 라인이 어긋난다. 라인 정돈을 우선해 미적용

5. 발행 프로세스

STEP 0
초안 수급 · 주제 점검 하이훅 HTML 초안 확보. 기존 발행글과 주제 중복 여부를 먼저 확인한다. 인접 주제가 있으면 각도를 달리 잡고 상호 링크를 계획한다. 시즌 콘텐츠는 시즌 2~3주 전 발행이 되도록 일정 역산.
STEP 1
검증 본 정책 2항 기준으로 통계·인용·시기성 정보를 전수 점검. 웹검색으로 1차 출처 확인 후 최신치 갱신, 검증 불가 항목은 삭제. 셀링부스터 수치는 조회 시점을 명기하고 발행 직전 재확인.
STEP 2
워싱 · 재구성 격식체 전환, 만연체 제거, 두괄식 재배열. 검증에서 삭제된 근거를 대체할 구조(표·단계·비교)를 세운다. 셀링부스터 기능은 문제 해결 흐름에 배치. 분량 하한 미달 시 누락 하위 주제를 섹션으로 신설.
STEP 3
형식 적용 · 산출 본 정책 4항 규격을 인라인으로 적용. 산출물은 붙여넣기용 본문 HTML 1파일. 셀링부스터 화면 캡처가 필요하면 파일명 자리표시자로 넣고 업로드 대상 목록을 함께 안내한다.
STEP 4
이미지 경로 확정 하이훅 원본 이미지는 경로 유지(UUID 한 글자만 바뀌어도 깨짐). 신규 캡처는 CMS 업로드 후 발급된 하이훅 URL로 교체. base64로 삽입된 초안 이미지는 파일로 추출해 별도 업로드(파일 용량 과다로 붙여넣기 실패 방지).
STEP 5
CMS 발행 ① HTML 파일을 텍스트 에디터로 열어 소스 전체 복사 (브라우저 렌더링 화면 드래그 복사 금지)
② CMS HTML 소스 모드에 붙여넣기
③ 일반 모드로 전환하지 않고 바로 저장 — 전환 시 에디터가 재정리하며 인라인 스타일과 h4 태그가 소실된다
④ 제목 입력란에 제목 등록 (본문 h2와 다르게, 검색어 앞배치)
STEP 6
발행 후 게시 화면에서 다크·라이트 모드 양쪽 확인. 표 라인·칩 대비·이미지 크기 점검. 이후 수정이 필요하면 CMS에서 직접 고치지 말고 원본 HTML을 수정해 다시 붙여넣는다(일반 모드 편집 시 전체 스타일 소실).
수정 요청 원칙: 오타 하나를 고치더라도 CMS 일반 모드를 거치면 문서 전체 스타일이 날아간다. 수정 사항은 원본 파일에 반영한 뒤 재붙여넣기하는 절차를 유지한다.

6. 하이훅 초안 → 발행본 변환 규칙

초안 요소발행본 처리비고
h1 대제목삭제 → h2 헤드라인으로 전환CMS가 게시글 제목을 h1으로 자동 출력

7. 발행 전 최종 체크리스트

진행 0 / 0항목을 클릭하면 체크됩니다 (저장되지 않음)
  • 기존 발행글과 주제 중복 확인, 인접 글 상호 링크 계획
  • 실명 인용·미검증 통계 잔재 0건
  • 통계는 1차 출처 + 최신치, 셀링부스터 수치는 조회 시점 명기
  • 기능 서술이 실제 동작과 일치 (미출시 기능은 예정 표기)
  • 본문 h1 0개 / h2 1개 / h3·h4 계층 정상
  • 분량 공백 제외 4,000자 이상
  • 표: collapse + 균일 테두리, 헤더 #1E2532 중앙 정렬
  • 이미지: max-width: 750px, border-radius: 30px, alt 누락·중복 없음
  • 이미지 URL이 원본 UUID와 정확히 일치, 로컬 파일명 잔재 없음
  • 본문 링크 20개 이하, 중복 없음 / 칩 8개
  • 형광펜 6곳 내외
  • FAQ 5개 이상 + <p><br></p> 스페이서
  • ※ 참고 자료, AI 고지 포함
  • on* 이벤트 속성 0개
  • 흰색 등 고정 색상 0개 (다크모드 대응)
  • 마무리가 항목별로 행갈이되어 있는지
  • 발행 후 다크·라이트 모드 양쪽 확인
