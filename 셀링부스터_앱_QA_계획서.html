1목적과 범위

운영서버에 배포된 앱 빌드를 대상으로 8/21(금)부터 9/11(금)까지 3주간 QA를 수행하고, 입점 승인 시점에 맞춰 9월 3주차 정식 오픈이 가능한 품질을 확보한다.

3-1. TC 설계 원칙

  • TC ID는 화면설계서 화면 번호와 매핑(예: S03-UI-004 = 화면 03 · UI 유형 · 4번)해 시트·카드·설계서 간 추적 가능하게 구성
  • 유형 구분: 기능(FN) · UI/디자인(UI) · 예외(EX) · 앱 특화(AP: 권한·오프라인·백그라운드·OS/해상도) · 보안(SE)
  • 우선순위: P1(핵심 플로우·결제·계정) → P2(주요 기능) → P3(부가·문구). P1은 1차 QA 첫 주(8/21~8/28) 내 전수 완료
  • 어드민 연동 TC: 배너·팝업·캘린더를 어드민에 등록 → 앱 노출·순서·기간·링크 이동 검증. 어드민 구축 완료(8/26) 이후 추가
  • 설계서와 실제 빌드가 다르면 결함으로 우선 등록하고, 기획 의도 변경이면 설계서를 갱신해 카드에 사유 기록

3-2. 공용 구글 시트 기록 규칙

항목규칙
상태값(담당자 필드)각 담당자 필드에 상태값만 표시 — Y: 정상 / N: 이슈 / NA: 기타·개선
실제결과(K열)이슈(N) 건만 공동 기재. 정상 건은 비움
환경앱: OS(버전) · 디바이스(기종) · 앱 빌드 버전 / 어드민: OS · 브라우저 · 해상도
재현 경로최소 3단계 내외 (예: 홈 → 키워드 분석 → 검색어 입력 → 조회)
기대결과 vs 실제결과설계서 기준 기대 동작과 실제 동작을 한 줄씩 대비 기재
스크린샷·영상영상 필수 권장(재현 경로가 담기도록). 정적 UI 이슈만 스크린샷 허용
재현 여부항상 발생 / 간헐적 / 환경 특수 중 택1. 간헐적·환경 특수는 발생 횟수·조건 병기

3-4. 릴리즈 판정 기준

TC 통과율(Y 건수 ÷ 전체 수행 건수, NA 제외)로 판정한다. 통과율과 무관하게 C·H 미해결 건이 있으면 릴리즈 불가.

판정통과율조치
릴리즈 가능85 ~ 100%잔여 M·L 건 오픈 후 처리 일정 합의 → 경영진 보고 → 오픈
조건부 가능66 ~ 84%잔여 건 목록·처리 일정·리스크를 명시해 보고, 실장 승인 시 제한 오픈. 미승인 시 재검증 기간 연장
불가~65%오픈 2안(9/30)으로 이동, 재검증 계획 재수립

5QA 종료 기준

  2. C·H 결함 0건(완료 상태), TC 통과율 85% 이상(릴리즈 가능 구간)
  3. M·L 잔여 건은 목록화하여 오픈 후 처리 일정 합의
  4. 핵심 플로우 회귀 테스트 통과(수동 + Maestro)
